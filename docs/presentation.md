# Repository presentation

The README helps a person understand the benefit, see an example, start using the skill, and recover from problems. Keep specialized editing rules in the behavior reference, package mechanics in architecture/setup, and historical validation in existing evidence records. Public descriptions should describe useful writing tasks, without individual pronoun policies or helper implementation in the opening.

The [directory listing draft](chatgpt-submission.md#listing-draft) follows this standard. The current runtime manifest remains unchanged because its exact bytes are bound to the existing behavioral captures; applying the draft to a future release needs fresh evidence rather than changing the historical record.

Use the same task labels as the sibling repositories where applicable: Try it, Get started, Get help, Update or remove, Where it works, Technical details, Contribute. Keep this project's writing examples and icon distinct. Use semantic headings, readable text, descriptive links, and short copyable prompts; important content must remain understandable without images or color.

Provide AI prompts and direct instructions. Label the intended surface above prompts. ChatGPT uses actual `@` selection; Codex uses `$` or its picker. Browser help must not imply an unlisted plugin has a public install route. Preserve per-turn guidance and put feature requirements beside the feature.

Download counters are optional **only when the displayed count is verifiably at least 100**. None is displayed because a qualifying public metric has not been established. Before adding one, record its source, meaning, date/window, and value; use conditional display or remove it if the displayed value falls below 100. Repository ZIPs, package downloads, and installations are different metrics.

## GitHub settings when publishing

Suggested About description: “Polish American English writing while keeping your meaning, voice, and formatting.” Keep the relevant writing/agent topics. The README is a useful destination until a separate docs site exists.

Use the existing icon and original/shareable examples. A future social preview should be readable at small sizes, use a 1280×640 canvas, and stay below 1 MB. Repository settings and directory publication are separate from this source change.
